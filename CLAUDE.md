# CLAUDE.md - AI Assistant Guide for Mój Mały Biznes

## Project Overview

**Mój Mały Biznes** (My Small Business) is a Laravel-based web application designed for Polish unregistered entrepreneurs ("działalność nierejestrowana"). It helps track income, expenses, generate invoices, and monitor monthly income limits required by Polish tax law.

**Status:** ⚠️ DEPRECATED - The application will cease operations on September 30, 2025, due to upcoming Polish KSEF requirements (February 2026) and insufficient resources for compliance adaptation.

**Primary Language:** Polish (UI), English (codebase)

## Quick Reference

## Architecture Overview

### Framework Architecture: Filament 3.2

**CRITICAL:** This is NOT a traditional Laravel MVC application. It uses Filament, a full-stack admin panel framework.

- **No traditional controllers** - Logic is in Filament Resources and Pages
- **No separate route definitions** - Routes auto-generated by Filament
- **Declarative forms and tables** - Defined in Resource classes
- **Livewire-based** - All interactions are Livewire components

### Application Structure

```
┌─────────────────────────────────────────┐
│          User Interface Layer           │
│  (Filament Resources, Pages, Widgets)   │
├─────────────────────────────────────────┤
│        Business Logic Layer             │
│    (Models, Observers, Scopes)          │
├─────────────────────────────────────────┤
│          Data Access Layer              │

```

### Multi-Tenancy Pattern

The application uses **automatic user-scoping** via `UserAccessScope`:

```php
// Applied to: Income, Expense, Contractor models
// Automatically filters: WHERE user_id = Auth::user()->id
```

**Never manually filter by user_id** - the scope handles it automatically.

## Observer Pattern (Critical!)

**All business logic and validation happen in Observers, not Controllers.**

### Observer Locations and Responsibilities

```
app/Observers/
├── IncomeObserver.php          # Validates monthly limits, min date (2020-01-01)
├── ExpenseObserver.php         # Expense business rules
├── InvoiceObserver.php         # Invoice validation
├── ContractorObserver.php      # Auto-assigns user_id
├── UserObserver.php            # User lifecycle management
├── IncomeItemObserver.php      # Updates parent Income total
├── ExpenseItemObserver.php     # Updates parent Expense total
└── InvoiceItemObserver.php     # Updates parent Invoice total
```

### Observer Registration

Observers are registered in `app/Providers/AppServiceProvider.php`:

```php
public function boot(): void
{
    Income::observe(IncomeObserver::class);
    Expense::observe(ExpenseObserver::class);
    // ... etc
}
```

## Database Schema

### Core Tables

#### users
- **Purpose:** Authentication and seller information
- **Key Fields:**
  - Standard Laravel auth: `email`, `password`, `remember_token`
  - Seller data: `seller_name`, `seller_tax_id`, `seller_country`, `seller_city`, `seller_postal_code`, `seller_address`, `seller_email`, `seller_phone`
  - `limit_category`: enum('default', 'unemployed')
- **Relationships:** hasMany Income, Expense, Invoice

#### incomes
- **Purpose:** Track revenue/sales
- **Key Fields:** `title`, `amount`, `date`, `notes`, `is_paid`, `user_id`, `contractor_id`
- **Relationships:** hasMany IncomeItem, Invoice; belongsTo User, Contractor

#### income_items
- **Purpose:** Line items for income records
- **Key Fields:** `title`, `quantity`, `uom` (unit of measure), `price`, `amount`, `order_column`
- **Sortable:** Yes (drag-drop ordering)

#### expenses
- **Purpose:** Track business costs
- **Key Fields:** `title`, `amount`, `date`, `notes`, `user_id`, `contractor_id`
- **Media:** Supports PDF receipt attachments (max 2MB, 10 files)

#### expense_items
- **Purpose:** Line items for expense records
- **Key Fields:** Same as income_items

#### contractors
- **Purpose:** Store customer/supplier information
- **Key Fields:** `name`, `tax_id`, `country`, `city`, `postal_code`, `address`, `email`, `phone`, `notes`, `user_id`

#### invoices
- **Purpose:** Generated PDF invoices
- **Key Fields:**
  - `invoice_number`, `issue_date`, `transaction_date`, `due_date`, `amount`
  - `title`, `correction_reason`
  - `tax_exemption_type`: enum('objective', 'subjective')
  - Denormalized contractor/seller data (copies from contractor/user)
  - `invoice_id`: self-reference for correction invoices
- **Relationships:** hasMany InvoiceItem; belongsTo Income, User, Contractor, Invoice (parent)

#### invoice_items
- **Purpose:** Line items for invoices
- **Key Fields:** Same as income_items

#### monthly_income_limits
- **Purpose:** Historical tax limit tracking
- **Key Fields:** `default`, `unemployed`, `starts_at`, `ends_at`
- **Note:** Enforces Polish "działalność nierejestrowana" limits

#### Additional Tables
- `media`: Spatie Media Library (receipts, invoice PDFs)
- `breezy_sessions`: Two-factor authentication sessions
- `socialite_users`: Social login connections (Google)
- `cache`, `sessions`, `jobs`, `failed_jobs`: Laravel standard

## Coding Conventions

### PSR Compliance
- **PSR-4:** Autoloading (strictly followed)
- **PSR-12:** Coding style (enforced by Laravel Pint)

### Naming Conventions

| Type | Convention | Example |
|------|-----------|---------|
| Models | Singular, PascalCase | `Income`, `InvoiceItem` |
| Tables | Plural, snake_case | `incomes`, `invoice_items` |
| Controllers | PascalCase + Controller | `IncomeController` |
| Variables | camelCase | `$monthlyIncome` |
| Methods | camelCase | `calculateTotal()` |
| Constants | UPPER_SNAKE_CASE | `MAX_UPLOAD_SIZE` |
| Routes | kebab-case | `/monthly-income-limits` |
| Foreign Keys | snake_case + _id | `contractor_id`, `user_id` |

### Code Organization Principles

1. **Business Logic in Observers** - Not in controllers or models
2. **Calculations in Models** - Static methods preferred (`Income::calculateTotal()`)
3. **UI Logic in Resources** - Filament form/table definitions
4. **Validation in Observers** - Enforce business rules on model events
5. **Relationships in Models** - Define all Eloquent relationships
6. **Queries via Scopes** - Reusable query modifications

### File Structure Standards

```php
// Model structure
namespace App\Models;

class Income extends Model
{
    // 1. Traits
    use HasFactory;

    // 2. Constants
    protected $fillable = [...];
    protected $casts = [...];

    // 3. Relationships
    public function user() { ... }
    public function items() { ... }

    // 4. Scopes
    protected static function booted() { ... }

    // 5. Accessors/Mutators
    public function getTotalAttribute() { ... }

    // 6. Business logic methods
    public function updateTotal() { ... }
}
```

### Currency Handling

- **Type:** Decimal(15,2)
- **Storage:** In lowest denomination (no need for cents conversion in PLN)
- **Calculations:** Use `bcmath` for precision (handled by Eloquent casts)

### Date Handling

- **Timezone:** Europe/Warsaw (set in .env)
- **Format:** Y-m-d for dates, Y-m-d H:i:s for timestamps
- **Minimum Date:** 2020-01-01 (enforced by IncomeObserver)

#### Example: Adding a new Model and Resource

1. **Create Model and Migration:**
   ```bash
   php artisan make:model Product -m
   ```

2. **Define Migration:**
   ```php
   Schema::create('products', function (Blueprint $table) {
       $table->id();
       $table->foreignId('user_id')->constrained()->cascadeOnDelete();
       $table->string('name');
       $table->decimal('price', 15, 2);
       $table->text('description')->nullable();
       $table->timestamps();
   });
   ```

3. **Configure Model:**
   ```php
   // app/Models/Product.php
   use App\Models\Scopes\UserAccessScope;

   class Product extends Model
   {
       protected $fillable = ['name', 'price', 'description'];

       protected $casts = [
           'price' => 'decimal:2',
       ];

       protected static function booted(): void
       {
           static::addGlobalScope(new UserAccessScope);
       }

       public function user()
       {
           return $this->belongsTo(User::class);
       }
   }
   ```

4. **Create Observer:**
   ```bash
   php artisan make:observer ProductObserver --model=Product
   ```

   ```php
   class ProductObserver
   {
       public function creating(Product $product): void
       {
           $product->user_id = Auth::id();
       }
   }
   ```

   Register in `AppServiceProvider`:
   ```php
   Product::observe(ProductObserver::class);
   ```

5. **Create Filament Resource:**
   ```bash
   php artisan make:filament-resource Product --generate
   ```

6. **Create Factory:**
   ```bash
   php artisan make:factory ProductFactory
   ```

   ```php
   public function definition(): array
   {
       return [
           'user_id' => User::factory(),
           'name' => fake()->words(3, true),
           'price' => fake()->randomFloat(2, 10, 1000),
           'description' => fake()->sentence(),
       ];
   }
   ```

7. **Write Tests:**
   ```bash
   php artisan make:test --pest FilamentProductResourceTest
   ```

## Testing Guidelines

### Test Structure

All tests use **Pest PHP** syntax:

```php
use App\Models\{User, Income};
use App\Filament\Resources\IncomeResource\Pages\CreateIncome;

uses(RefreshDatabase::class);

it('can create income', function () {
    $user = User::factory()->create();
    actingAs($user);

    $contractor = Contractor::factory()->create();

    livewire(CreateIncome::class)
        ->fillForm([
            'title' => 'Test Income',
            'amount' => 1000,
            'date' => now()->format('Y-m-d'),
            'contractor_id' => $contractor->id,
            'items' => [
                [
                    'title' => 'Item 1',
                    'quantity' => 1,
                    'uom' => 'szt',
                    'price' => 1000,
                    'amount' => 1000,
                ],
            ],
        ])
        ->call('create')
        ->assertHasNoFormErrors();

    $this->assertDatabaseHas('incomes', [
        'title' => 'Test Income',
        'amount' => 1000,
        'user_id' => $user->id,
    ]);
});
```

### Testing Filament Resources

```php
use function Pest\Livewire\livewire;

// Test Create
livewire(CreateIncome::class)
    ->fillForm([...])
    ->call('create')
    ->assertHasNoFormErrors();

// Test Edit
livewire(EditIncome::class, ['record' => $income->id])
    ->fillForm(['title' => 'Updated'])
    ->call('save')
    ->assertHasNoFormErrors();

    ->callAction('delete');

// Test Table
livewire(ListIncomes::class)

```

### Testing Best Practices

1. **Always use `RefreshDatabase` trait** - Ensures clean database state
2. **Use factories** - Never create models manually in tests
3. **Test happy path and edge cases** - Both valid and invalid scenarios
4. **Test business logic** - Especially Observer validations
5. **Test relationships** - Ensure proper data association
6. **Test scopes** - Verify UserAccessScope isolation
7. **Use descriptive test names** - Clear "it" statements

### Factory Usage

```php
// Create single model
$income = Income::factory()->create();

// Create with relationships
$income = Income::factory()
    ->for(User::factory())
    ->for(Contractor::factory())
    ->has(IncomeItem::factory()->count(3))
    ->create();

// Create multiple
$incomes = Income::factory()->count(5)->create();

// Make (don't persist)
```

## Important Notes for AI Assistants

7. **Don't skip tests** - Always write tests for new features
8. **Don't modify vendor files** - Use proper override mechanisms
9. **Don't commit .env** - Use .env.example
10. **Don't forget queue processing** - Some operations are queued
11. **Don't hardcode limits** - Use MonthlyIncomeLimit model

### Common Pitfalls

1. **Forgetting Repeater Validation:**
   - Income/Expense/Invoice require at least one item
   - Enforced in Filament form, not Observer
   - Test this explicitly

2. **PDF Generation Failures:**
   - wkhtmltopdf must be installed
   - Path must be set in .env (`WKHTML_PDF_BINARY`)
   - Check for special characters in templates

3. **Monthly Limit Enforcement:**
   - Calculated per calendar month
   - Depends on user's `limit_category`
   - Uses MonthlyIncomeLimit model for thresholds
   - Validated in IncomeObserver

4. **Storage Quota:**
   - Cloudflare R2 used for production
   - Max 2MB per file, 10 files for expenses
   - User has storage limit (tracked in User model)

5. **Self-Referencing Invoices:**
   - Correction invoices reference parent invoice
   - Must handle null `invoice_id` properly
   - Cascade deletes can affect corrections

6. **Time Zone Issues:**
   - App timezone: Europe/Warsaw
   - Always use Laravel date helpers
   - Store UTC in database, display in app timezone

7. **Social Login:**
   - Google OAuth configured
   - Users can have multiple social connections
   - SocialiteUser model stores connections

### Polish Tax Law Context

The application enforces Polish "działalność nierejestrowana" (unregistered business activity) rules:

1. **Monthly Income Limits:**
   - Default category: varies by year (stored in MonthlyIncomeLimit)
   - Unemployed category: higher limit
   - Exceeding limit triggers notification
   - No earlier than 2020 records allowed

2. **Invoice Requirements:**
   - Must include seller and buyer tax IDs
   - Date of issue vs. date of transaction
   - Tax exemption types: objective or subjective
   - Correction invoices reference original

3. **Expense Tracking:**
   - Receipts required (PDF uploads)
   - Used to calculate net profit
   - Not tied to invoices
